# 動画中間構造の構成スキル

台本やネタから、絵コンテ的な中間構造JSON（`scenes` ＋ 4レーン）を**組み立てる**ための手順書。
ここに書くのは「何が正しい構造か（仕様）」ではなく「素材からどう構造を作るか（手順）」。
正式な仕様・全プロパティの定義は `references/spec.md` を参照。

このスキルが作る成果物は、**実タイムラインの一歩手前の中間表現**。
時間は具体値で書くが、見た目（スタイル）は意味的な印だけを置き、具体レシピは書かない。

---

## 着手前に揃えるもの

1. **元コンテンツ** … 台本・ナレーション原稿・構成案・箇条書きのいずれか。
2. **スタイルカタログ**（`style-catalog.json`）… 使える印（`tone.emphasis` 等）の一覧。
   これが**印のenum**であり、ここに無い印は使ってはいけない。

カタログが見当たらない場合は、ユーザーに在処を尋ねるか、最小の既定印
（`telop.default` / `audio.default` 程度）だけで組み、「カタログ未指定で組んだ」旨を必ず添える。
存在しない印を勝手に発明しないことが、後段のコンパイルを壊さないための最重要ルール。

---

## 構成手順

上から順に進める。各ステップは「前のステップの出力を埋める」形になっており、
**ドライバ（尺を決めるレーン）→ フィラー（それを埋めるレーン）→ 装飾（テロップ・SE・オーバーレイ）**
の順で組むのが事故が少ない。

### Step 1. シーンに分割する

**1シーン＝1つの連続した時計＋だいたい1つのナレーションの塊**、を基本単位にする。
台本のナレーションの切れ目・話題の変わり目で切る。1文〜数文で1シーンが目安。

- 切りすぎない（シーンが細かすぎると `scenes` が冗長になり、跨ぎたい要素も増える）。
- 逆に1シーンに別話題を詰め込まない（同期や差し替えが追いにくくなる）。
- 各シーンに `id`（`s1`, `s2`, …）を振る。

### Step 2. シーンごとに「ドライバ」を決める

そのシーンの尺を**何が決めるか**を選び、`duration` に書く。

- **ナレーション主導（最頻）** … 音声がドライバ。`"duration": { "ref": "audio.end" }`
- **映像主導**（尺の決まったb-roll等） … `"duration": { "ref": "video.end" }`
- **固定尺**（タイトル数秒など） … `"duration": 5` のように具体値。

迷ったらナレーション主導。語りに映像を合わせるのが最も自然で破綻しにくい。

### Step 3. ドライバのレーンを最初に敷く

ドライバが音声なら、**audio レーンを先に完成させる**。

- ナレーションを発話単位（テロップ1枚に対応する粒度が扱いやすい）に分割する。
- 先頭要素は `"t": [0, "auto"]`、以降は `"t": ["after", "auto"]` で背中合わせに連結する。
  `"auto"` は「実測尺（TTSの発話長など）を使う」の意味で、終端が後で確定する。
- `role` を付ける（ナレーションは `"voice"`）。
- **id は「他レーンから参照される要素」にだけ**振る（`v1`, `v2`, …）。
  テロップを同期させたい発話には id を振り、そうでなければ省略する。

```jsonc
"audio": [
  { "id": "v1", "role": "voice", "source": "tts://本日のテーマは", "t": [0,       "auto"] },
  { "id": "v2", "role": "voice", "source": "tts://中間構造です",   "t": ["after", "auto"] }
]
```

### Step 4. フィラー（映像）でシーンを埋める

ドライバが決めた尺を、映像で埋める。

- **1カットで通す** … `"t": [0, "auto"]`（素材長をそのまま）か、シーン尺に合わせる。
- **カット割り（モンタージュ）** … `"t": ["after", "auto"]` で複数クリップを連結。
- **`t`（配置）と `in`/`out`（トリム）を混同しない。**
  `t` はシーン時計上のどこに置くか、`in`/`out` は元素材の何秒〜何秒を切り出すか。

```jsonc
"video": [
  { "source": "broll.mp4", "in": 5, "out": 20, "t": [0, "auto"] }
  //                        ↑素材5-20秒を      ↑シーン0秒から配置
]
```

素材長とシーン尺がズレても、ここでは気にしない（凍結/ループ等はコンパイラの方針）。
配置 `t` が実使用尺、`out` は素材上限のキャップとして扱われる。

### Step 5. テロップを乗せる

- **音声同期**（最頻）… ドライバ音声の発話に合わせる。
  発話に振った id を使い、`"t": [{ "ref": "v1.start" }, { "ref": "v1.end" }]` のように囲う。
  これでTTSの尺が変わってもテロップが追従する。
- **独立配置** … 具体時刻で `"t": [1.0, 5.0]`。
- 各テロップに `style`（意味的な印）を付ける。`text` は表示文字。
- カット割りを跨ぐテロップも、同じシーン時計に乗るので普通に `"t": [1.0, 6.0]` で書けば自動で跨ぐ。

### Step 6. SE・オーバーレイを足す（必要なら）

- **効果音** … audio レーンに `"role": "se"`、`"t": [3.5, "auto"]`。
- **オーバーレイ画像**（ロゴ等）… overlay レーンに `"t": [0.5, "auto"]` ＋ 位置系の印。
- **オーバーレイ動画**（PiP/インサート）… `in`/`out` でトリムし、`t[0]` の時刻に配置。

### Step 7. すべての要素にスタイルの印を付ける

各要素について「これは**何のための**要素か」を考え、カタログから**意味で**印を選ぶ。

- 強調したい決め台詞 → `tone.emphasis`、ふつうの字幕 → `telop.default`。
- **見た目（色・太さ）で選ばない。意図で選ぶ。** カタログの `intent` / `feeling` を手がかりにする。
- カタログに無い印は使わない。変化を付けたいときは `params`（意味的な値のみ。生のpx/hexは禁止）。

### Step 8. id を最小化する

参照されていない要素の `id` を削る。
残る id は「他から名指しされる特別な要素」だけになり、構造の意図が読みやすくなる。

### Step 9. 自己検証する（出力前に必ず）

下の「自己チェック」を全項目通してから出力する。

## パターン集（よく使う構成の雛形）

### ナレーション1文＝テロップ1枚（音声同期の基本形）

```jsonc
{
  "id": "s1",
  "duration": { "ref": "audio.end" },
  "audio": [
    { "id": "v1", "role": "voice", "source": "tts://まずは結論から", "t": [0, "auto"] }
  ],
  "telop": [
    { "t": [{ "ref": "v1.start" }, { "ref": "v1.end" }], "text": "まずは結論から", "style": "tone.emphasis" }
  ],
  "video": [
    { "source": "broll.mp4", "in": 0, "out": 8, "t": [0, "auto"] }
  ]
}
```

### 連続ナレーション（after で詰める）

```jsonc
"audio": [
  { "id": "v1", "role": "voice", "source": "tts://一つ目は",   "t": [0,       "auto"] },
  { "id": "v2", "role": "voice", "source": "tts://二つ目は",   "t": ["after", "auto"] },
  {            "role": "voice", "source": "tts://最後に",     "t": ["after", "auto"] }
]
```

### カット割り（映像モンタージュ）

```jsonc
"video": [
  { "source": "a.mp4", "in": 0,  "out": 4,  "t": [0,       "auto"] },
  { "source": "b.mp4", "in": 10, "out": 13, "t": ["after", "auto"] }
]
```

### カット跨ぎテロップ

```jsonc
// 上のモンタージュ(a→b)に対し、境界を跨ぐテロップを1枚乗せるだけ
"telop": [
  { "t": [1.0, 6.0], "text": "カットを跨ぐ説明", "style": "telop.default" }
]
```

### スプリットスクリーン（par は使わず重ね＋layout印）

```jsonc
"video": [
  { "source": "left.mp4",  "in": 0, "out": 5, "t": [0, "auto"], "style": "layout.split-left"  },
  { "source": "right.mp4", "in": 0, "out": 5, "t": [0, "auto"], "style": "layout.split-right" }
]
```

### 効果音

```jsonc
"audio": [
  { "role": "se", "source": "whoosh.wav", "t": [0.0, "auto"] }
]
```

### オーバーレイ画像（常駐ロゴ）／動画（インサート）

```jsonc
"overlay": [
  { "source": "logo.png",    "t": [0.5, "auto"], "style": "position.corner" },
  { "source": "insert.mp4", "in": 2, "out": 6, "t": [3.0, "auto"] }
]
```

### 全体BGM（シーンを跨ぐ要素）

シーンを跨ぐ要素（全体BGM等）は、`scenes` の1段上に**シーンと同じ形のレーン**を置く。
（仕様上は保留扱いだが、跨ぎが必要なら下の形を採用する。詳細は `references/spec.md` の §10.1）

```jsonc
{
  "meta": { ... },
  "audio": [
    { "role": "music", "source": "bgm.mp3", "t": [0, { "ref": "scenes.end" }] }
  ],
  "scenes": [ ... ]
}
```

## 自己チェック（出力前）

- [ ] **start が具体か参照になっている。** `start` に `"auto"` 単体は不可。
      派生してよいのは `end`（尺）だけ。これを破ると時間が循環して解けなくなる。
- [ ] **`t`（配置）と `in`/`out`（トリム）を取り違えていない。**
- [ ] **`ref` の参照先が同じシーン内にある。** シーンを跨ぐ `ref` は禁止（跨ぎは全体レーンへ）。
- [ ] **`style` がすべてカタログに存在する印。** 発明した印が無い。
- [ ] **`appliesTo` 違反がない**（telop 専用の印を audio に付けていない等）。
- [ ] **`params` に生の px / hex / カラーが無い**（意味的な値だけ）。
- [ ] **各 telop の `t` が `0 ≤ start < end ≤ シーン尺` に収まる。**
- [ ] **id は参照される要素にだけ付いている**（無駄な id を残していない）。
- [ ] **`duration` が、そのシーンに実在するレーンを指している**（音声が無いのに `audio.end` を指していない）。
- [ ] **出力は妥当なJSON**（実運用はコメント無し。説明が要るときだけ別途JSONCで示す）。

## 進め方のヒント

- 入力が曖昧（素材ファイル名が無い、ナレーションだけ等）なら、**プレースホルダの `source`
  （`broll.mp4`、`tts://〜` 等）で先に構造を組み**、実ファイルの割り当ては後段に委ねてよい。
  この中間構造は意図的に過少指定でよい。
- 大きな台本は、まず Step 1 のシーン分割だけをユーザーに見せて合意を取ると、後の手戻りが減る。
- 既存の中間構造を**編集**する依頼では、シーン単位・要素単位で差分を当てる。
  id を持つ要素は参照されている可能性があるので、id の変更・削除は参照元も一緒に直す。
